## What Is Being Tested

Each request has test scripts that validate:

- **Status code**: for example 200 or 201
- **Performance**: response time and response size thresholds
- **Response format**: valid JSON, body is an object or array
- **Data correctness**: response values match the data sent from the environment (first name, middle name, last name, date of birth)
- **Data types**: fields are strings, numbers or arrays as expected
- **Non-empty fields**: names, date of birth, technical details, addresses, phone numbers
- **Nested structure**: `TechnicalDetails`, `Address`, `Permanent_Address`, `Current_Address` and `PhoneNumber` in the final student details response
- **Business response**: `status` is `true` and the success message is returned for update, technical skills, address and delete

## Known Failures

| Request | Failed Test | Error |
| --- | --- | --- |
| Create Technical Skills | Verify that Status code is 201 or not | expected response to have status code 201 but got 200 |
| Create Student Address | Verify that Status code is 201 or not | expected response to have status code 201 but got 200 |

**Analysis:** Both endpoints return `200 OK` instead of `201 Created`, while the response body (`status: true` and the success message) is correct. The record is created successfully, so this is a mismatch between the expected status code in the test and the actual API behavior. Either the assertion should be updated to accept `200`, or the API should be changed to return `201`.

## Prerequisites

- [Node.js](https://nodejs.org/) (LTS recommended)
- [Postman](https://www.postman.com/) (to create or edit the collection)
- Newman and the htmlextra reporter

```bash
npm install -g newman
npm install -g newman-reporter-htmlextra
```

Verify the installation:

```bash
newman --version
```

---

## How to Run the Tests

Run the collection with the environment and generate the HTML report:

```bash
newman run collection/Student.postman_collection.json \
  -e environment/Student.postman_environment.json \
  -r htmlextra \
  --reporter-htmlextra-export reports/
```

The report is saved inside the `reports/` folder with a timestamped file name.

### Run with CLI output only

```bash
newman run collection/Student.postman_collection.json \
  -e environment/Student.postman_environment.json
```

### Run with a dark theme report

```bash
newman run collection/Student.postman_collection.json \
  -e environment/Student.postman_environment.json \
  -r htmlextra \
  --reporter-htmlextra-darkTheme
```

## Viewing the Report

Open the generated file in any browser:

```

```

The report includes:

- Summary dashboard (requests, assertions, failures, skipped tests)
- Timing and data statistics
- List of failed tests with error messages
- Per-request details: method, URL, headers, request body, response body and assertion results
- Light and dark theme toggle

### Optional: Host the report with GitHub Pages

1. Move or copy the report to a `docs/` folder and rename it to `index.html`.
2. In your repository go to **Settings > Pages**.
3. Select the branch and the `/docs` folder, then save.
4. The report will be available at `https://<username>.github.io/<repository>/`.
